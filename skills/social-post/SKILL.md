# 社群平台貼文

依任務需要協助規劃、撰稿、修訂與成效檢視。把文案草稿、實際發布、成效判讀分成不同步驟；不把未驗證的寫作假設包裝成平台演算法規則。

## 工作路由

| 使用者意圖 | 流程 | 交付 |
|---|---|---|
| 排內容、想題材 | 規劃 | 目標受眾、單篇目的、題材選項與簡短內容日曆 |
| 寫文、改稿、指定語氣 | 撰稿 | 可直接複製的純文字版本；必要時附平台欄位 |
| 學習個人聲線 | 聲線整理 | 從使用者明確提供或指定的樣本歸納特徵，先交校準摘要供確認 |
| 看數據、找有效模式 | 成效檢視 | 觀察事實、可能解釋、待測假設分開呈現 |
| 發布、回覆留言 | 外部操作 | 只有在有可用且授權的工具、明確平台/帳號/內容範圍及本輪確認時才可執行；否則提供可複製稿與人工步驟 |

## 撰稿前

1. 先沿用使用者當輪已提供的題材、受眾、平台、素材及限制，不重複詢問。
2. 若仍缺必要資訊，只問最關鍵的一項；可合理先寫時，標示假設並給未校準初稿。
3. 有個人語氣需求時，只使用當前可讀取且使用者授權的樣本或語氣卡。公開範本與一般記憶不等於已讀到使用者的私人文案。
4. 依平台表面選擇格式：一般文字、圖片字卡、Reels/Shorts 說明或 YouTube 標題等不可混為一種文案。使用者要跨平台同步時，除非明確要求平台化改寫，維持一份共同正文。
5. 一篇只設一個主要目的、一個核心主張與一個 CTA。題材沒有證據時，不虛構個人經驗、數字、引言或成果。

## 產稿與修稿

- 開頭盡快說清楚觀點、可驗證結果、反差或問題；避免空泛開場與顧問式套話。
- 正文以目標平台和使用者樣本的節奏撰寫。沒有同類樣本時，不硬套其他格式的長度、換行或發文時段。
- 預設交付可直接貼上的純文字；不擅加 Markdown、標題、表情符號、標籤或外部連結。若使用者或所選樣本要求，則依需求加入。
- 黑底白字等圖卡文案要與貼文說明分開，避免把長篇正文塞進圖片。
- 修訂同一篇時，保留使用者已刪除或指定不要出現的格式，不把單篇修訂擴成永久偏好。
- 交稿前核對主張、事實來源、開頭、結尾、段落、換行、標點、表情符號、英文混用、標籤與 CTA；不合要求先修正再交稿。

## 個人聲線與隱私

- 只分析使用者提供或明確指定的貼文；若樣本不足，說明目前是初步觀察，不宣稱已完整學會其風格。
- 將可觀察特徵與主觀推測分開，例如句長、段落、標點是可觀察項，受眾偏好則需更多證據。
- 私人貼文、帳號資訊、成效數據、個人識別資訊和憑證不得寫入公開技能或公開範例。
- 新資料是待觀察案例，不自動變成永久寫作規則；先呈現差異與理由，再由使用者決定是否採用。

## 成效分析

1. 先記錄平台、格式、發布時間、資料擷取時間與可見指標；缺少的欄位標示未知，不補猜。
2. 比較時優先選同平台、同格式、相近主題與相近發布後時間的樣本。樣本少時只描述差異，不下普遍結論。
3. 區分「看到什麼」「可能原因」「還需要怎麼驗證」。同時改變題材、素材、標題和時間就不是乾淨的單因子測試。
4. 不因少數高流量案例宣稱存在爆紅公式、保證觸及或黃金發文時段；時間、標籤與文案技巧都只能當待測假設。

## 發布與平台規格

- 生成草稿不等於發布。發布前須在當前對話取得明確確認，核對平台、帳號、完整文案及素材。
- 沒有已授權的外部操作工具時，不能宣稱已發布、已排程或已回覆留言。
- 不協助繞過登入驗證、CAPTCHA、平台限制或隱私設定；未授權不執行按讚、追蹤、批量留言等操作。
- 字數上限、Hashtag 建議、演算法與介面規格可能變動。若任務仰賴精確或最新規則，查平台官方來源並標示查核日期；否則以使用者指定格式為準。
