# 混元網頁建模與角色動畫

將指定原圖製成可瀏覽、可驗證的角色模型與動畫。預設採 **混元網頁 → Blender 整理 → Mixamo → Blender 修權重 → GLB／FBX 與預覽**。混元生成使用 Browser Use；不自行改用生成 API、TripoSR 或 Colab。

## 主對話與 subagent 分工

若你已是受派的模型子代理，直接執行下方建模工作，不再因讀到本 Skill 逐層派工。

- 主代理確認原專案、輸入圖片、預期動作及本次已授權範圍，然後依 [子代理派工](references/delegation.md) 派出模型工作代理。不要在主對話親自跑生成、等待排隊或反覆輪詢。
- 子代理負責瀏覽器操作、計時、下載、Blender 修整、綁骨、動作與驗收，將實體產物和精簡結果交回主代理。
- 主對話簡短回報已派工即可繼續接受其他需求；完成、確實需使用者操作的阻礙或新增範圍決策，才集中回報。若執行環境不能跨回合持續跑，明說限制，不宣稱子代理會在背景自動完成。
- 普通測試細節直接決定，不為減面數、命名、例行修整、一般重試反覆詢問或額外製作備份。保留輸入與必要的原始高模／工作副本，便於修整及比較。
- 不把這個 Skill 當成新付款、接受新協議、變更既有資產等操作的概括授權；沿用當次已確認事項，不重問。

## 建立本次工作

依原專案現行保存規則，產物放 `<project>/Codex/`，不要寫到 Skill 安裝目錄。來源圖可引用原路徑；需要獨立輸入副本時放 `inputs/`，記錄 SHA256。輸出用角色與執行版本分目錄，避免混用前次結果。

建立精簡執行紀錄，至少包含：輸入檔與雜湊、網頁模型版本、生成設定、任務識別（若畫面提供）、各階段時間、檔案位置／大小／雜湊、目前完成階段、動作來源及未解決問題。不要保存登入憑證、Cookie、Token 或含授權參數的下載網址。

## 混元網頁生成

1. 使用目前環境的 Browser Use 工具，先讀其有效操作文件；以即時頁面狀態定位控制項，不重用案例座標、分頁編號或舊選單索引。官方入口：`https://3d.hunyuan.tencent.com/`。
2. 上傳使用者指定的同一張原圖。確認圖生 3D、圖片預覽、當前模型版本和面數／材質選項。可用時優先選使用者已接受的 V3.1；版本改變時記錄實際選擇，不假定介面不變。
3. 在按生成前記錄提交時間，生成完成時記錄首次完成觀測時間。將登入／排隊／生成／傳輸／本機修整分開；若漏掉完成瞬間，保留上下界或首次完成觀測上限，不把網站估計或整段等待當成精確推論耗時。
4. 任務已提交時先查畫面狀態，避免因操作逾時而重複生成、再次消耗點數。
5. 下載原始 GLB。成功提示不是落地證據：核對檔案存在、大小、GLB 標頭、雜湊與實際匯入。若下載卡住，按需讀 [下載與品質問題](references/pitfalls.md)。

五個以上模型也沿用使用者指定的網頁方式，依頁面真正允許的任務數排程；不要把 API 的並行配額套到網頁。每個角色獨立輸入、計時與驗收，不直接用單件時間乘數估算總耗時。

## Blender 外觀與動畫用網格

- 先匯入真實 GLB，以一致相機、光線檢查正面、側面、背面及斜前方；對照原圖的臉、髮型、冠帽、袖口、衣袍、配件與身體比例。單張正面圖推得的背面只稱合理補建。
- 留下必要的原始高模與動畫工作副本。按用途減面，例如本案例的約 8 萬三角面只是起點，不能用面數高低當品質證明。
- 減面前檢查重合頂點與拓樸；焊接容差依模型尺度決定。減面後檢查五官斑點、法線和 UV／袖口接縫；需要時從高模重新烘焙底色到工作網格，保留原高模材質。底色烘焙版不要宣稱完整保留 PBR。
- 明確統一朝向、尺度與地面位置，再輸出適合 Mixamo 的 FBX 或 OBJ。選擇原圖 T／A pose 可減少後續困難，不另改角色造型以迎合流程。

## Mixamo 綁骨與動作

1. 入口：`https://www.mixamo.com/`。沿用已登入的正確帳號；需要本人完成登入時才交接。遇到替換既有角色提示，依當次授權處理，不將前次授權延伸到其他帳號或資產。
2. 上傳工作副本，確認角色正面，再標下巴、手腕、手肘、膝蓋與胯部。寬袖下的手肘、長袍內的膝與胯部按人體比例定位，不把衣服邊緣當關節。
3. 簡化手部可選 No Fingers；需要手指動作時才選含手指骨架，關節數不固定套用司馬遷案例。
4. 先測待機、揮手，再按使用者需要增加說話手勢、走路等。記錄實際動作名稱、參數、幀率、裁切與循環設定；不要把同名動作當作同一素材。
5. 第一份通常下載帶蒙皮 FBX，後續同一骨架可下載不帶網格的動作，再在 Blender 對齊。確認骨架與 rest pose 相容。只有線上 Review／播放完成時，狀態仍是「線上綁骨／動作預覽」。
6. 確認下載檔實際落地，才開始本機動作處理。下載等待有上限；同一接收機制連續失敗時，檢查即時狀態並改採有依據的替代路徑，不反覆掛住主代理或宣稱已取得檔案。

## 權重修正與交付驗收

- 在 Blender 檢查整段動作的正、側、背面。重點是寬袖被上臂／前臂拉扯、手臂穿身體、長袍被左右腿扯開、帽帶漂移、腳底滑動與地面穿透。
- 長袍下襬可改由骨盆、衣袍輔助骨或受控混合權重帶動；需要行走時保留擺腿空間，不把整件袍一律鎖死。帽帶等附屬物按需要加輔助骨，不承諾 Mixamo 自動完成衣物或表情。
- 使用實際下載的 Mixamo 動作修整／烘焙。若改用自行製作動作，明確記錄來源變更，不能沿用 Mixamo 完成的名義。
- 匯出 GLB（嵌入貼圖）、FBX（貼圖可攜），需要可編輯工程時附 `.blend`。重新匯入交付檔，確認蒙皮、動作長度、切換、實際變形及貼圖。循環動作才檢查循環接點；腳步動作依預期位移判斷，不一律要求零位移。
- 用 `scripts/inspect_glb.py` 檢查結構。`--require-animation` 可攔截缺少蒙皮／骨架動作的 GLB，但結構通過仍要做播放及視覺驗收。
- 交付可閱讀的 HTML 比較／耗時報告、實際網格多角度圖、必要動作預覽及精簡成果清單。網頁入口不要直接指向 `.md`；靜態版本停用動畫控制並標示狀態。
- 主代理最後回報：可開啟的成果、實際選用版本、已驗證動作、時間及未完成項目。若只取得靜態模型，交付靜態成果並清楚標記動畫仍未完成。
